# CDF Updater — תוסף Excel

תוסף שמוסיף לאקסל לשונית **CDF** עם חלונית צד שעושה ארבעה דברים:

1. **ייבוא קבצים** — `CDF_List_Export` מחליף את הגיליון **GCC**, ו-`650` מחליף את הגיליון **Mantra**. כל קובץ **מוחק ומחליף** את הגיליון שלו בקובץ הגדול (באותו מיקום).
2. **הרצת האלגוריתם** — אלגוריתם ה-CDF (`CDF_Algorithm_2026-11-05`) מומש כקוד (`cdf-algo.js`), בשלבים. לוחצים **Check changes**, רואים כל תא שישתנה (לפני → אחרי, ולפי איזה כלל), את **Cross-check**, ואז **Apply**.
3. **שורה חדשה לחריג** — Claude קורא את PDF החריג ואת PDF ה-ATT (כולל התמונות) וממלא את השדות, ואתה עובר על הטופס ומאשר. הכל דרך מנוי Claude שלך, בלי עלות נוספת.
4. **שליחת מייל** — בוחרים מה לשלוח ולמי, ונפתחת טיוטה מוכנה ב-Outlook.

כל פעולה נרשמת בגיליון **UPDATE LOG** עם הערך הקודם והחדש של כל תא, וגם רשימת CDF שהופיעו בקובץ העדכון ולא נמצאו בבסיס.

> שלבים 1, 2 ו-4 לא מוציאים נתונים מהמחשב. בשלב 3 אתה מעלה את קבצי ה-PDF ל-claude.ai בעצמך. כדאי לוודא מול אבטחת מידע שזה מותר לסוג המסמכים האלה.

## התקנה (פעם אחת, כ-10 דקות)

### שלב 1 — manifest.xml (כבר מוכן)
`manifest.xml` כבר מוכן לחשבון GitHub ‏**NPerryK** (כתובת: `https://nperryk.github.io/cdf-updater/`). אין צורך לערוך אותו — רק לוודא שהמאגר נקרא בדיוק `cdf-updater`.

### שלב 2 — העלאה ל-GitHub ופרסום ב-Pages
1. ב-github.com: **New repository** ← שם: `cdf-updater` ← **Public** ← **Create repository**.
   (GitHub Pages בחשבון חינמי עובד רק עם מאגר ציבורי. במאגר יש רק קוד וכללים — אף פעם לא להעלות אליו קבצי נתונים.)
2. לחץ **uploading an existing file**, גרור פנימה את **כל** הקבצים והתיקיות (`assets`, `lib`, `tests` וכל השאר) ← **Commit changes**.
3. **Settings ← Pages** ← Source: **Deploy from a branch** ← Branch: **main**, תיקייה **/ (root)** ← **Save**.
4. אחרי 1–2 דקות פתח בדפדפן:
   `https://nperryk.github.io/cdf-updater/taskpane.html`
   אמורה להופיע החלונית עם הודעה "Opened outside Excel" ונורית ירוקה **RULES OK** בראש החלונית. אם כן — האירוח עובד.

### שלב 3 — התקנה באקסל

**Excel למחשב (Windows)** — דרך תיקייה משותפת:
1. צור תיקייה (למשל `C:\AddinCatalog`), שים בה את `manifest.xml` המעודכן.
2. קליק ימני על התיקייה ← **Properties ← Sharing ← Share** ← **Share**. העתק את הנתיב שמופיע (נראה כמו `\\שם-המחשב\AddinCatalog`).
3. באקסל: **File ← Options ← Trust Center ← Trust Center Settings ← Trusted Add-in Catalogs**.
4. הדבק את הנתיב ב-**Catalog Url** ← **Add catalog** ← סמן **Show in Menu** ← OK ← OK.
5. **סגור ופתח את אקסל מחדש.**
6. **Home ← Add-ins ← Advanced** ← בחלון למעלה **SHARED FOLDER** ← בחר **CDF Updater** ← **Add**.
7. תופיע לשונית **CDF** בסרגל ← **Open Updater**.

**Excel באינטרנט** — **Home ← Add-ins ← Advanced** ← בתפריט למעלה מימין **Manage my add-ins ← Upload My Add-in** ← בחר את `manifest.xml`.

> אם "Trusted Add-in Catalogs" נעול אצלכם (מדיניות ארגונית), צריך לבקש מ-IT לפרוס את `manifest.xml` דרך Microsoft 365 admin center (Integrated apps).

## שימוש

1. פתח את הקובץ הגדול (`CDF REQ STATUS AC 1 - 01574`) ← לשונית **CDF ← Open Updater**.
2. **שלב 1:** גרור את `CDF_List_Export` ואת `650` — אפשר את שניהם יחד, לכל מקום בשלב 1, וכל קובץ נכנס למקום שלו לפי השם ← **Replace sheets** ← **Yes, replace**. קובץ עם שם אחר מקבל אזהרה.
3. **שלב 2:** **Check changes** ← עבור על **Cross-check** ועל הטבלה (אדום = לפני, ירוק = אחרי, ובעמודה האחרונה מספר הכלל) ← **Apply N changes**.
4. בדוק את הגיליון **UPDATE LOG** אם צריך לראות מה השתנה או לשחזר ערך.

> מומלץ לשמור את הקובץ לפני "החל" — לא בטוח ש-Ctrl+Z יבטל שינויים שתוסף כתב.

## שורה חדשה לחריג (שלב 3)

השלב עובד דרך מנוי Claude שלך ב-claude.ai, בלי עלות נוספת.

### הדרך המהירה: Claude Project (הגדרה חד-פעמית)
ב-Project ההנחיות כבר שמורות, ולכן לא צריך להעתיק ולהדביק הנחיה בכל פעם.

**הגדרה, פעם אחת:**
1. בחלונית, בשלב 3: **Skip the prompt: set up a Claude Project**.
2. ב-claude.ai: **Projects** ← צור Project, למשל "CDF new rows".
3. **Copy project instructions** ← הדבק ב-Instructions של ה-Project ← שמור.
4. העתק את הכתובת של ה-Project מהדפדפן (מתחילה ב-`https://claude.ai/project/`), הדבק בחלונית ← **Save**.

**מעכשיו, בכל פעם:**
1. **Open the Claude project** ← צ'אט חדש ב-Project ← גרור את קבצי ה-PDF ← Enter. אפשר כמה זוגות בבת אחת.
2. בתשובה: **Copy** על בלוק הקוד ← **Ctrl+V** בתיבה **Claude's reply**. התשובה נקראת מיד, בלי לחיצה נוספת.
3. CDF אחד: מופיע הטופס שלו. כמה CDFs: מופיעה רשימה (ראה בהמשך).

**כשההנחיות משתנות:** לכל גרסה של ההנחיות יש קוד קצר (למשל `E0C60E`), ו-Claude מחזיר אותו בכל תשובה.
- אם ערכת את `ai-prompt.txt` אחרי שהעתקת את ההנחיות ל-Project, החלונית מציגה **The instructions changed** עם כפתור העתקה. מדביקים מחדש ב-Project, וזהו.
- אם הגיעה תשובה עם קוד ישן, הטופס מציג אזהרה, כדי שלא תכתוב שורות לפי כללים ישנים בלי לשים לב.
- הקישור ל-Project נשמר במחשב שלך. כדי שיישמר גם אחרי ניקוי ה-cache של Office, אפשר לכתוב אותו גם ב-`rules.txt` בשורה `CLAUDE_PROJECT "https://claude.ai/project/..."`.

### בלי Project
**Copy prompt** ← **Open Claude** ← הדבק את ההנחיה, גרור את ה-PDF ושלח ← **Copy** על בלוק הקוד ← **Ctrl+V** בתיבה.

אם התשובה לא חוזרת כבלוק JSON נקי, בקש מ-Claude: "החזר שוב רק את בלוק ה-JSON".

### כמה CDFs בתשובה אחת
מופיעה רשימה של כל ה-CDFs, ולכל אחד:
- היעד: **New row N** (כחול) או **Updates row N** (כתום, ה-CDF כבר קיים בקובץ).
- תחילת התיאור, ונקודות לבדיקה מסומנות בכתום.
- תיבת סימון. מה שלא מסומן לא נכתב.

ואז אחת משתיים:
- **Write N rows** — כותב את כל המסומנים בפעולה אחת. כל CDF חדש מקבל את השורה הפנויה הבאה, וכל תא נרשם ב-UPDATE LOG.
- **Check one by one** — טופס מלא לכל CDF, עם אפשרות לתקן לפני הכתיבה: "CDF 1 of 3" ← **Add row** או **Skip**.

**הטופס:**
- ליד כל שדה רואים את **אות העמודה ואת שם הכותרת שלה בקובץ**. כך מיד רואים אם שדה הולך לעמודה הלא נכונה.
- "לבדוק" — דברים ש-Claude לא היה בטוח בהם.
- אם ה-CDF כבר קיים בקובץ, כתוב באיזו שורה, וערכים קיימים שיוחלפו מסומנים.
- אם Claude לא ראה את שמות הקבצים, שדות הקישור ריקים — אפשר להקליד בהם את שם הקובץ.
- מתקנים מה שצריך ← **Add row**. שדה ריק לא נכתב ולא מוחק ערך קיים.

**התאמה:**
- את המיפוי של שדה ← עמודה קובעים בשורות `NEWROW` ב-`rules.txt`. **חובה לאמת אותו מול שורת הכותרות של הקובץ לפני שימוש אמיתי.**
- הנוסח ש-Claude מקבל (סגנון התיאור, מה לסמן לבדיקה) נמצא ב-`ai-prompt.txt`. אפשר לערוך אותו ב-GitHub כמו את הכללים.
- קישורים: `NEWROW A = LINK ATT "..\PDF\"` כותב בעמודה A קישור לתיקייה + שם הקובץ. נתיב יחסי (כמו `..\PDF\`) נמדד מהתיקייה של קובץ האקסל.

## שליחת מייל (שלב 4)

1. **What to send:**
   - **Changes from the last run** — שינויים מההרצה האחרונה
   - **CDFs not found in the last run** — CDF שלא נמצאו
   - **New rows added today** — שורות חדשות של היום
   - **Report: ...** — כל דוח שהוגדר ב-`REPORT` בקובץ הכללים

   שלושת הראשונים נקראים מהגיליון UPDATE LOG, אז הם עובדים גם אחרי שסוגרים ופותחים את אקסל.
2. **נמענים:** כותבים ב-To/Cc, או לוחצים על קבוצה שמורה. **Save recipients as a group** שומר רק במחשב הזה.
3. **Prepare email** ← תצוגה מקדימה ← **Open draft in Outlook**. המייל לא נשלח לבד; אתה לוחץ "שלח" ב-Outlook.
4. אם המייל ארוך, הטבלה מועתקת אוטומטית ובטיוטה רק מדביקים (**Ctrl+V**). **Copy as table** נותן טבלה מעוצבת להדבקה בכל מייל.

> המאגר ב-GitHub ציבורי. אל תכניס ל-`rules.txt` או ל-`ai-prompt.txt` כתובות מייל, שמות של אנשים או נתונים אמיתיים מהפרויקט. קבוצות נמענים — רק דרך החלונית.

## אלגוריתם ה-CDF (שלב 2)

האלגוריתם מומש כקוד בארבעה שלבים. החלונית מציגה איזה שלב כבר פעיל:

| שלב | מה הוא עושה | מצב |
|---|---|---|
| 1 | GCC → CDF: עמודות R, S, T, Y, Z בשורת העוגן; כלל 10 (Final Approval של Igor → GCC!AM = Released); Completed; Cancelled; הכפיל 052; טבלאות CDF SUMMARY שנגזרות מ-GCC | ✓ פעיל |
| 2 | Mantra → CDF: AA, AB, U:X, שורות הפתרון, תאריך סגירה | בהמשך |
| 3 | כתיבת CDF SUMMARY המלא ו-EMAIL DRAFT | בהמשך |
| 4 | BACKUPDATA, שחרורים ב-24 שעות / 7 ימים, ERROR | בהמשך |

**Cross-check — איך יודעים שהנתונים נכונים:**
- **Control totals** (לפי 130.6): ‏CDF STATUS TOTAL = מספר חריגי GCC שקיימים ב-CDF; סכום התחנות = מספר ה-Open; ‏WHERE + לא משויכים = Open בתחנה 3. ‏✗ פירושו פער שצריך לבדוק — והפירוט מראה איפה.
- **CDF SUMMARY tables**: כל טבלה מחושבת מחדש ומושווית למה שכתוב היום ב-CDF SUMMARY בחוברת, שורה מול שורה (Now / Result). בהרצה על אותם נתונים — הכל `=`. אחרי ייבוא GCC חדש — ההבדלים הם בדיוק מה שהשתנה.
- **כל שינוי** מופיע בטבלה עם הכלל שגרם לו (20.2, 20.3.1, 00.6, 10…) ושורת המקור ב-GCC (מעבר עכבר על השורה).
- הקוד נבדק מול הרצת ה-05/11 שלך: על אותם נתונים — 0 שינויים, ‏3/3 בדיקות, ‏6/6 טבלאות זהות.

**כשהאלגוריתם מתעדכן:**
- **רשימות ומיפויים** (תחנות, ספקים, מי משחרר ב-Final Approval, טבלאות ה-Pending, הכפיל) — נמצאים ב-`rules.txt` ואפשר לשנות אותם בלי קוד.
- **לוגיקה** — שלח את קובץ האלגוריתם החדש; הקוד מתעדכן לפי ההבדלים מהגרסה הקודמת ונבדק שוב מול החוברת העדכנית.
- השורה `CDF_ALGORITHM "2026-11-05"` ב-`rules.txt` אומרת לאיזו גרסה החוברת מצפה. אם היא שונה מהגרסה שבקוד — החלונית מזהירה שהקוד צריך עדכון.

## עריכת הכללים (rules.txt)

עורכים את `rules.txt` ישירות ב-GitHub (אייקון העיפרון ← **Commit**). התוסף קורא אותו מחדש בכל לחיצה על "בדוק שינויים" (עד כ-10 דקות עיכוב בגלל מטמון של GitHub Pages; אפשר ללחוץ "טען מחדש").
לבדיקה מהירה בלי GitHub: בחלונית ← **Load file from computer** (נשמר עד שלוחצים **Back to the GitHub file**).

| פקודה | משמעות |
|---|---|
| `IMPORT 1 "GCC" FILE "CDF_List_Export"` | קובץ מספר 1 מחליף את הגיליון GCC. ‏`FILE` = שם הקובץ שאמור להיכנס לכאן (קבצים מנותבים לפיו, וקובץ אחר מקבל אזהרה) |
| `IMPORT 2 "X" FROM "Data"` | קובץ 2 מחליף את X, ולוקחים מהקובץ את הגיליון Data (ברירת מחדל: הגיליון הראשון) |
| `ALGORITHM "שם"` | מתחיל אלגוריתם חדש (אפשר כמה; רצים לפי הסדר) |
| `BASE FIRST` / `BASE "שם"` | גיליון הבסיס: הראשון בחוברת, או לפי שם |
| `UPDATE "INTEGRATOR"` | הגיליון שממנו האלגוריתם קורא את העדכונים |
| `BASE_START_ROW 3` | שורת הנתונים הראשונה בבסיס (מתחת לכותרות) |
| `UPDATE_START_ROW 2` | שורת הנתונים הראשונה בעדכון |
| `MATCH UPDATE.A = BASE.C` | לפי מה מתאימים שורות (בלי רגישות לרווחים/אותיות גדולות) |
| `COPY UPDATE.M -> BASE.T` | העתקת ערך (כולל פורמט תאריך) |
| `SET BASE.Z = "טקסט"` / `= TODAY` / `= NOW` / `= 5` | כתיבת ערך קבוע |
| `IF BASE.T = "9 - FINAL APPROVAL" COPY ...` | פעולה בתנאי. אופרטורים: `=` `<>` `CONTAINS` `NOT CONTAINS`, ערך `EMPTY`, חיבור תנאים ב-`AND` |
| `ON_CHANGE SET BASE.R = TODAY` | רץ רק אם משהו בשורה באמת השתנה |
| `SKIP_EMPTY YES` | לא לדרוס ערך קיים בתא ריק מהעדכון |
| `DATE_FORMAT "dd/mm/yyyy"` | פורמט לתאריכים שהתוסף כותב |
| `LOG "UPDATE LOG"` / `LOG NONE` | גיליון היומן |
| `CDF_ALGORITHM "2026-11-05"` | שלב 2 מריץ את אלגוריתם ה-CDF (במקום בלוק `ALGORITHM`), והגרסה שהחוברת מצפה לה |
| `STATION "Conversion ENG" = "3 - Conversion Engineer"` | מיפוי תחנה מ-GCC!AM ל-CDF!S (תחנה בלי מיפוי מדווחת כשגיאה) |
| `SUPPLIER "SIE/ANN" = "ANN/SIE"` | ספק לטבלת WHERE ARE THE CDFS, לפי CDF!P |
| `FINAL_APPROVAL_RELEASE "Igor Golodriga"` | כלל 10 |
| `PENDING_TABLE "MOR PENDING TABLE" "Mor Ifrah"` | טבלת Pending לאדם |
| `DUPLICATE_CDF "A330-1-052 (another)"` | כפיל שלא נספר ב-CDF STATUS |
| `NEWROW_SHEET FIRST` / `"שם"` | הגיליון שאליו נכנסות שורות חדשות |
| `NEWROW_KEY C` | עמודת מספר ה-CDF (לפיה בודקים אם כבר קיים) |
| `NEWROW_START_ROW 3` / `NEWROW_HEADER_ROW 1` | שורת הנתונים הראשונה / שורת הכותרות |
| `NEWROW H = AI.DESCRIPTION` | שדה מה-AI. שדות: `CDF DATE PRIORITY DESCRIPTION OEM DRAWING INSTALLATION CODE INITIATOR` |
| `NEWROW C = CDF` / `= TODAY` / `= "-"` | מספר CDF משם הקובץ / תאריך היום / ערך קבוע |
| `NEWROW A = LINK ATT "<תיקייה>"` | קישור לקובץ ה-ATT (או `LINK MAIN` לקובץ החריג) |
| `REPORT "נושא" WHERE BASE.T = "..." COLUMNS C, T, X` | דוח למייל (אפשר `AND`, `SHEET "שם"`, `FROM_ROW 3`) |
| `EMAIL_GROUP "שם" "a@x.com; b@y.com"` | קבוצת נמענים (רק אם המאגר פרטי) |

הכללים רצים לפי הסדר, ותנאי `IF` בודק את הערך **אחרי** הפעולות שלפניו (לכן `IF BASE.T = ...` רואה את הסטטוס החדש).
אם יש שגיאה בקובץ, החלונית מציגה את מספר השורה והסיבה, ולא תאפשר להריץ.

## עדכון התוסף עצמו
כשמגיעה גרסה חדשה:
1. במאגר ב-GitHub: **Add file ← Upload files** ← גרור את הקבצים החדשים (אפשר את כולם) ← **Commit changes**. קובץ באותו שם מוחלף אוטומטית.
2. קובץ שהוסר מהגרסה החדשה לא נמחק לבד: לחץ עליו במאגר ← **⋯** ← **Delete file** ← **Commit changes**.
3. חכה 1–2 דקות, ואז סגור ופתח את החלונית באקסל.
